# Changes that stay in their own files

A task stays in its own files when it changes one feature in one place, without dependencies, migrations, generated
code or central configuration. It may run beside another task once the parallel analyst clears both.

One place: one component, one page, one screen, one form, one dialog, one endpoint handler, one controller, one
service class, one function, one script, one command, one report, one email template, one document.

Local work: fix a bug in a named file, add validation to one form, add a field to one screen that already has its
data, add a test next to the code it tests, adjust the logic of one function, add logging to one handler, change the
behaviour of one button, improve one error message, add an empty state to one list, add sorting to one table.

Words that mark it: in this file, in this component, on this page, only, just, single, local, isolated, this
function, this endpoint, this screen, this module only.
