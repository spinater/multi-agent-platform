# Tasks to plan first

A task to plan first is a whole project, not one change. The planner splits it into several smaller tasks with
dependencies before any agent starts.

Building something new from scratch: build a new system, a new platform, a new application, a new app, a new service,
a new product, a booking system, an appointment system, a queue system, an ecommerce shop, a marketplace, a point of
sale, an inventory system, a CRM, an ERP, a school system, a clinic system, a hospital system, a chat application, a
social network, a blog platform, a learning platform, a multi-tenant SaaS, an admin panel and a customer app together.

Whole-system scope: the entire system, the whole system, the whole application, end to end, every screen, all pages,
all modules, many screens, many modules, many services, several services, backend and frontend and database together,
mobile app and web app and API together, user side and admin side, roles for customers staff and managers.

Rebuilds and migrations of everything: rewrite the application, rebuild from scratch, redesign the architecture,
migrate to another framework, port to another language, move to another database, replace the backend, split the
monolith into microservices, move data from the old system to the new system, replace the legacy system.

Long lists of separate requests in one task, a roadmap, phases, milestones, epics, a version two, months of work,
a product launch, requirements for a full product.
